# 一、研究目标与中期工作概况

本课题围绕零基础人群的数字绘画体验展开，研究如何将图像的笔触表达转化为可理解、可执行的操作引导，帮助使用者开始绘画、持续推进并获得创作满足感。论文题目为“基于笔触拆解算法的数字绘画辅助系统交互设计研究——以‘星迹智绘’为例”。研究所关注的“不会画、不想画、怕画不好”，分别对应操作方法不明确、行动意愿不足以及对结果的不确定感。系统希望通过清晰的下一笔提示降低这些障碍；这些目标需要在后续用户实验中检验，不能仅根据界面完成情况判断已经实现。

开题阶段确定了研究方向、问题意识和产品构想，尚未形成可运行的系统。开题以来，本阶段工作主要集中于四个方面：搜集与梳理笔触式渲染及神经绘画相关算法；融合方法思想并完成适合浏览器交互的笔触规划实现；搭建选图、绘画、反馈和作品保存的交互流程及视觉界面；开发支持对比实验的数据采集、研究管理和分析展示模块。目前已形成可操作、可演示的“星迹智绘”网页原型，研究进入以真实使用检验设计的准备阶段。

本研究将算法、交互和评价放在同一条研究主线上。算法提供有序的绘画动作，交互设计将位置、方向、颜色、宽度和进度转译为易于理解的提示，系统记录实际操作与主观反馈，后续实验再评价这种帮助是否有效。这里的“拆解”是用有限笔触近似重建图像，并非还原原画作者的真实作画过程；“辅助”也不意味着由系统代替用户完成全部作品。用户亲手作画与系统演示需要在功能和记录中加以区分。

截至本报告编写时，已完成主要程序建设、算法工程整合、交互设计和研究流程的软件验证，尚未开展真实参与者的预试和正式对比实验。本文的程序截图、算法阶段图及功能演示用于说明中期建设成果；研究界面中的示例记录来自隔离演示环境，不构成用户实验数据。接下来的重点是实施用户测试、检查任务负担，并依据观察结果优化交互与完善论文论证。

# 二、相关算法的搜集、理解与方法整合

## 2.1 笔触式渲染的基础原理

Hertzmann提出的多尺度曲线笔触方法是本课题的重要基础文献[1]。该方法用较大的笔刷建立画面，再用逐渐缩小的笔刷修整与相应模糊参考图存在差异的区域；曲线沿图像梯度的垂直方向延伸，形成具有绘画感的笔迹。论文还把笔刷尺寸、曲率及颜色变化等组织为可调风格参数，为“将图像表示为动作序列”和“通过参数形成不同笔触外观”提供了方法参照。

在面向交互设计的阅读中，我重点区分了图像重建与人的绘画任务。自动渲染主要关心生成图像，逐笔指导还需要考虑笔数、寻找起点的难度、位置跳转与动作顺序。因而本项目以多尺度表达为基础，将有限动作预算、可预测的空间顺序以及每一步可显示的笔触参数纳入实现目标。文献提供的是方法思想，具体的预算分配、扫描规则和界面提示则由本项目结合应用场景设计。

## 2.2 神经绘画研究的参照价值

Huang等将绘画描述为连续笔触决策，通过神经渲染器和基于模型的强化学习生成笔触序列[2]；Zou等将参数化笔触渲染与图像相似度优化相结合，讨论神经渲染及参数搜索问题[3]；Hu等进一步区分“在哪里画”和“画什么”，通过动态预测绘画区域组织重建过程[4]。这三类研究帮助本课题理解有限笔触表达、参数优化反馈以及绘画区域组织之间的联系。

本项目对这些研究采用方法层面的综合参照：保留可回放的参数化动作、以重建误差评价候选笔触，并明确组织区域访问顺序。当前运行程序采用显式搜索和解析颜色拟合，没有训练或调用上述论文的策略网络、神经渲染器及动态区域模型。因此，本课题的工作定位是面向交互需求的算法适配与系统设计，不能把相关论文的性能结论直接当作本系统的实验结果，也不将这种思想整合表述为多个神经模型的直接融合部署。

## 2.3 方法选择与系统结构

在浏览器中完成规划可以让用户选图后直接获得绘画引导，也便于将取消、进度反馈和重新尝试纳入交互。当前方法把输入图像转成一组包含起止点、宽度、颜色及遍次信息的笔触，由画布模块按顺序显示和绘制。计算过程放在Web Worker后台线程中，避免主要交互长时间被计算阻塞；研究模块则保存经过审核的参考图和计划，使同一批次的参与者使用一致材料。图1展示了从输入到绘画指导、再到研究记录的结构。

# 三、约1000笔的有序规划算法实现

## 3.1 有限预算与五遍尺度组织

当前默认规划器以最多1000次笔触规划尝试为预算，从白色画布开始重新组织整幅图像。系统不先生成大量笔触再截取前1000笔，也不把参考原图叠在结果下方充当重建。每次只接受能够改善目标误差且路径有效的笔触，因此实际输出可能略少于预算。约1000笔是目前的工程配置，作用是在细节表现和操作数量之间提供可检验的方案，尚不能视为零基础使用者的最佳工作量。

绘画顺序分为五遍：大色块、中色块、形体、小笔触和细节。各遍分别采用固定宽度，整组宽度由大到小递减；每遍按网格逐行访问，从左上到右下推进，并在当前区域中选择仍需修整的位置。这里的空间顺序是区域访问顺序，不要求每一笔的端点都严格沿一条对角线排列。笔触可以跨越网格边界，其颜色拟合与误差评价始终基于同一张共享画布，避免把各块分别绘制后再硬性拼接。

## 3.2 残差驱动搜索与整笔颜色拟合

输入图像先保持比例缩放，并将透明部分合成到白底上。当前1000笔配置的分析图最长边不超过256像素。程序计算目标图与当前画布的逐像素差异，同时适度提高局部颜色变化明显区域的权重。这个权重用于保留边缘附近的信息，并不意味着系统具备物体识别能力；人脸、文字和复杂纹理中的重要语义细节仍可能丢失。

每个候选笔触采用圆头直线段，即胶囊形覆盖范围，参数包括中心位置、方向、长度和当前遍次的固定宽度。搜索先在当前区域依据残差选择候选位置，再比较64个候选，并对较优结果进行36次局部调整。笔触颜色根据整条笔刷的覆盖范围、当前画布和透明度共同求解，而不是只取某个起点像素。这样既考虑原图局部颜色，也考虑已经绘制的底色对叠涂效果的影响。

## 3.3 面向交互的优化成果与适用边界

本阶段的算法工作形成了三个相互配合的优化方向：用预算分配控制总体动作规模；用五遍固定尺度和逐行访问建立容易理解的绘画节奏；用完整覆盖范围拟色和逐笔反馈保持有限笔触下的图像表达。体验画布采用0.85的规划透明度，研究画布采用不透明笔刷，规划时分别匹配对应参数。两种模式共用核心方法，但材料版本区分保存，不能混用两种渲染方式的预览作为同一结果。

对莫奈样图，现有工程验证得到998笔，五遍累积笔数为60、179、398、678和998，笔宽没有出现由小反增的跳变。这个结果说明预算和顺序约束已经运行，并且可以输出实际阶段图；它不代表任意照片都能在1000笔内达到相同精细程度。图像相似性、单笔可执行性和任务总负担仍需共同判断，低像素误差不能代替美感评价或人的绘画表现。

当前算法也不恢复真实大师的作画步骤，不进行自动语义分区。其可解释性在于尺度、区域顺序和误差变化均可直接检查。对于细线、密集小物体和强纹理材料，需要保留失败样例，观察重要形体是否被覆盖，以及小笔触是否细到难以跟随。下一阶段将结合预试确定任务材料和预算，而不是仅凭理想重建图的精致程度提高笔数。

# 四、交互流程与UI设计建设

## 4.1 信息架构与创作入口

“星迹智绘”已经建立首页、选图、绘画、作品查看、产品介绍及研究测试等主要页面。普通体验路径围绕“选择想画的图—获得有序笔触—亲手绘画—保存作品”组织；用户测试通过独立入口进入统一任务。首页突出“开始我的第一幅画”的主操作，将较长介绍默认折叠，减少初次进入时需要阅读的信息。产品介绍页面则承担完整功能说明、算法原理和文献来源展示，避免把技术细节集中放入绘画任务界面。

## 4.2 绘画中的提示、控制与反馈

绘画界面以画布为中心，当前笔触通过半透明区域、数字起终点和方向箭头表示。数字、圆圈、箭头和路线会随笔触尺寸同比缩放，减少细小笔触被大图标遮挡的情况。用户默认获得完整引导，也可在工具中选择适度提示或仅保留起点。进度与遍次说明共同告诉用户当前处于大色块建立还是细节修整阶段，使“下一笔”与整幅画的形成过程建立联系。

参考原图置于月亮伙伴面板中，按容器适配显示，点击可以放大查看并恢复。面板可移动、锁定和收起为方圆图标，帮助使用者根据画布位置安排信息。底部工具栏把模式、画笔与常用操作集中呈现，按钮提供悬停文字提示，教程入口解释不同工具的作用。沿星迹模式支持撤销，使误操作具备可恢复性，也让用户可以重新尝试当前动作。

[[图5]]

普通体验提供沿星迹、自动续画和自由星域三种使用方式。沿星迹强调按照当前提示动笔；自动续画用于观察序列怎样构成画面，逐笔间隔可在200毫秒至1秒之间调整，默认1秒，暂停后保持当前模式和进度；自由星域直接响应使用者的绘画手势。绘画过程中可调整笔宽、颜色和风格，笔宽数字用整数显示。自动演示和伙伴辅助完成属于体验功能，研究条件中禁用，以保留真实手绘结果。

## 4.3 视觉语言与六种风格笔刷

界面采用浅色背景、深色描边、大圆角和清晰阴影，以黄色突出主操作，以紫色表示引导与状态，辅以薄荷绿区分完成反馈。星点、星迹和月亮伙伴形成统一视觉语言，对应起点、绘画路径和过程提示。设计意图是降低专业绘画软件的工具压迫感，同时使下一步操作足够明确。色彩、角色与动效是否确实让用户更愿意开始，还需要通过后续观察和反馈检验。

自由绘画实现了莫奈、梵高、高更、伦勃朗、毕加索和萨金特六种风格预设。它们保留用户输入的路径，通过宽度曲线、路径扰动、分段和纹理改变笔迹外观。这里采用的是程序化参数表达，并非训练后的大师风格模型，也没有从大师原作中采集足以推导这些数值的笔迹数据库。图6中的笔迹由当前引擎绘制，用于展示相同手势经过不同预设后的差异。

# 五、程序与实验平台的开发建设

## 5.1 前后端与数据流程

程序以Next.js、React和TypeScript搭建页面与状态管理，浏览器Canvas承载参考图、引导和实际笔迹，Web Worker运行较重的图像规划。服务端提供研究配置、入组、轮次记录、作品保存、评分和导出接口，使用持久化数据库及文件目录管理研究材料。算法模块与绘画操作分离，研究材料保存版本和哈希，便于核对某一份记录使用了哪张图片、哪套笔触计划和哪一版规则。

普通体验与研究任务采用不同的使用边界。普通体验允许自行选图、切换风格与观察自动续画；研究任务由研究者统一设置材料、工具能力和时限。同一研究码关联同一人的两轮任务，重复研究码会被提示，不作为进入任意已有记录的凭证。研究者工作台集中查看测试记录、材料状态和配对结果，参与者无需选择后台批次。实际测试是否开放由材料审核和批次发布状态控制，软件功能完成不等于某个研究批次已经开始招募。

## 5.2 已搭建的五步用户测试流程

参与者侧的流程组织为“进入—熟悉工具—第一轮—第二轮—完成对比”。进入时说明用途、预计时间、保存内容与退出方式，并确认研究同意及参与条件。练习图自动准备，参与者主动开始90秒练习；每轮绘画前填写两道自评题，然后直接开始任务，避免在准备页面之间反复跳转。两轮之间安排休息，第二轮结束后显示配对结果，口头访谈由研究者在后台记录。图7概括了该流程与两种实验条件。

当前每轮设置12分钟上限，轮间休息2分钟，两轮前后均采集简短感受。前测关注再次绘画意愿和担心画不好，后测再加入体验满足感及完成类似任务的信心，采用七级回答并允许不回答。题目是围绕本项目目标编写的简短自评，尚不能视为已验证的标准心理量表。正式采集前还需通过预试检查语言是否容易理解、任务是否过长以及参与者是否把引导当作必须全部完成的考核。

# 六、阶段性成果与待验证问题

本阶段已形成可运行的网页原型、独立的笔触规划模块、由粗到细的五遍序列、六种自由笔刷、交互教程与产品说明，以及覆盖研究执行和记录管理的前后端模块。文献阅读已转化为具体的方法选择、实现说明和参考来源；UI设计已从页面表达落实到可操作的上传、提示、撤销、模式切换和保存流程。这些成果使课题具备开展用户测试的条件，构成中期工作的主要完成内容。

当前待验证的问题主要涉及任务负担与交互有效性。1000笔可改善部分图像的细节表达，但大量逐笔操作可能增加等待与重复动作；由粗到细的顺序更容易说明，却不保证每名用户都能理解局部笔触与原图之间的关系。参考图、画布、提示卡和工具栏的注意力分配也需要实际观察。后续将重点记录犹豫、误触、反复查看提示和提前结束的位置，以判断问题来自材料难度、算法动作还是界面组织。

研究解释同样需要明确边界。同图重复绘画会产生记忆和熟悉效应，AB与BA平衡只能缓解，不能完全消除；单次自评意愿不能证明长期习惯形成；更快结束也可能源于提前放弃。分析速度时必须结合完成度、结束原因及作品内容，分析满意度时要注意亲手创作感与系统帮助之间的关系。论文将把这些限制纳入讨论，并保留与预期不一致的结果。

## 7.1 开展预试并优化交互

下一阶段首先执行6名零基础参与者的预试。预试重点是确认用户能否理解说明、进入练习、独立开始绘画、使用提示并提交作品，以及同一材料在两条件下的任务负担是否合理。研究者将观察关键犹豫点、记录口头反馈，并核查日志、问卷和作品是否配对完整。预试数据用于发现设计和测量问题，不与正式数据直接混合用于证明假设。

根据预试结果，优先优化与核心任务有关的交互：控制提示信息量、调整面板遮挡与工具触达、明确开始和结束含义、改善细小笔触的可辨识性，并检查撤销是否符合用户预期。材料与笔触预算也根据真实操作时间和完成情况共同确定；不预设名画级复杂材料必须在12分钟内完成1000笔。优化后进行复验，再冻结正式材料、算法计划、界面、问卷和评分规则，使条件之间保持可比。

## 7.2 执行正式对比实验与结果分析

正式研究拟取得24名参与者的有效配对记录，招募数量和纳入条件结合预试及导师意见最终确定。参与者使用统一设备和输入方式，对同一图完成A、B两条件，遵循平衡顺序与一致时限。研究者按照统一说明执行，不在某一条件额外提供绘画帮助；口头访谈重点询问哪种方式更容易开始、何时最想停止，以及哪幅作品更有“自己画出来”的感受。

分析以作品完成度与再次绘画意愿为主要指标，启动等待、任务耗时、停顿、担忧和满足感作为辅助解释。当前平台提供配对差值、方向统计和双侧精确符号检验，并对两项主要指标进行Holm校正。正式分析前将明确缺失记录、超时、退出和技术故障的处理，报告差异及不确定性，避免只选择有利指标。作品评分尽量隐藏条件信息，并检查两位评分者的分歧；界面风格仍可能暴露条件时，将如实说明盲评限制。

## 7.3 完成论文写作与设计总结

论文写作与实验执行并行推进。现阶段可以完成研究背景、相关方法、算法实现、交互设计与系统建设章节；实验结束后补充用户表现、访谈、讨论和设计建议。最终论证围绕“有序笔触引导怎样帮助零基础用户开始并推进绘画”展开，将软件功能、过程证据和主观体验联系起来，而非仅罗列页面或以算法预览代替用户结果。研究将据此总结适用情境、局限和后续改进方向。
