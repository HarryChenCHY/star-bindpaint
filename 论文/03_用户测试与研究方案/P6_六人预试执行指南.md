# P6 六人预试执行指南

入口：http://localhost:3001/admin/studies/pilot 。从研究工作台也可进入。研究者口令沿用已有配置，不写入本文。

## 执行顺序

1. 在研究工作台核对当前算法材料与评分清单，保存并发布预试批次。旧材料不会自动升级。
2. 六位真实参与者分别从 /study 完成筛选、同意、练习、系统分配的 AB/BA 两轮、后测和访谈。
3. 两位评分者从 /rater 对两轮作品独立评分。
4. 打开六人预试看板，点击“读取 / 刷新”。逐人显示练习、传统条件、指导条件、访谈和双人评分。超时但正常完成后测可算流程完成，不代表作品达标；技术故障、未完成重测、撤回者不算完整预试。
5. 测试中发现的问题在看板登记。影响采集、公平比较或研究解释的问题标为“阻断”；其他可用性建议标为“一般”。问题只写现象，不写姓名、联系方式。
6. 修复后填入修复与复验说明，点击解决；再次出现可以重新打开。修改带修订号并由后端记录历史，同时编辑冲突会要求刷新。
7. 实际核对设备操作、任务负担、评分规则、保存导出和备份恢复，填写复核说明后保存。1000 笔与 12 分钟的适配性必须实际验证，不凭算法能生成就勾选完成。
8. 下载预试执行记录 JSON，用于研究过程归档。页面只根据现有记录计算进度，不生成参与者、问卷或评分。

## 正式发布条件

后端检查：至少六人完成练习、两条件终态和后测、访谈，且两条件都具备双人评分；当前材料已审核；四项复核针对当前计划哈希；没有未解决的阻断问题。满足后仍保留原正式发布检查，不自动发布。

看板“满足条件”只表示软件记录完整，研究负责人仍需确认这些活动由真实人员执行。一般问题可以留作后续改进，阻断问题不能靠不记录或随意降级绕过研究判断。

## 保存与版本

问题保存为私有 SQLite 中的 pilot_issue 记录，复核保存为 pilot_review。修改前后内容写入 audit。记录属于预试过程管理，不混入绘画行为指标或作品评分。问题保留最初发现时的计划哈希；即使材料改变，未解决阻断问题仍需要处理。

复核与当前计划哈希绑定，材料改变后旧复核失效但保留历史。已入组的材料仍不能原地修改；本次没有改变原有入组或时限规则，也没有自动创建新研究批次。

浏览器中的 JSON 下载包含当前预试进度、问题和复核快照；完整修改历史仍保存在后端审计表。请按既有研究备份方式归档私有数据库。

## 任务负担复盘（新增）

看板增加传统/指导条件的任务用时、有效落笔、停留次数、双人评分完成度和达标提交用时中位数，每项显示有效人数 n。逐人展开可核对暂停、隐藏、撤销与指导记录。用时条相对于当前时限显示，任务用时差按同一人的“指导－传统”计算，并显示 AB/BA 配对数。

仅使用每个条件的最新尝试，未结束、技术故障、撤回、排除和缺少结束事件的记录不进入组汇总。未齐评分保留为空；指导统计按当前计划编号去重，推进包含跳过，不代表画完，重复返回不会放大比例。检测到无法对应计划的指导事件时不计算占比。

点击“保存复盘到后端并下载”将不可覆盖的 JSON 快照保存到私有 pilot-reviews/{导出ID}.json；数据库保存导出时间和 SHA-256，页面可重新下载最近十份已存报告。普通“下载预试执行记录 JSON”仍是即时快照。报告来自同一后端指标函数，不在浏览器另算一套。

复盘目录已纳入 study-backup.mjs。执行参与者撤回清理时，该批次在线复盘快照也会删除；已经下载及离线备份依旧按原研究流程管理。复盘只是任务适配检查，不自动调整材料、时限或正式研究结论。
