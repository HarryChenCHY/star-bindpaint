# 审核摘要

文档状态：待用户审核，尚未启动程序改造。版本：v1.0；日期：2026 年 9 月 10 日。

编写依据：《星迹智绘_论文思路与对比实验及程序改造规划.docx》、项目当前代码，以及本次提出的“实验全流程在程序内完成”和“简化画优先、200 笔以内、轮廓 → 大色块 → 小色块”要求。本文件将上一份研究方案转为可实施、可验收的工程计划。原论文规划与学校模板保留不变。

建议把项目改造成“绘画体验 + 实验执行 + 数据管理与分析”的完整系统。参与者在程序中完成登记、同意、练习、两轮绘画、问卷和访谈；研究者在程序中配置材料、监控进度、处理异常、组织评分、导出数据与查看对比报告。论文需要的原始记录、指标口径和分析版本都能追溯。

“全流程在程序内”不等于全程无人判断：零基础筛选按自报标准判断，作品完成度由两名评分者在程序中独立评分，程序自动计算结果；技术故障与排除由研究者按预定规则确认。禁止用算法相似度或指导步骤完成率冒充客观作品完成度。

## 1.2 第一版范围与后续范围

第一版必须完成：实验闭环、可靠保存、共同评分、可复算报告、200 笔阶段规划、必要的状态动效和体验入口整合。研究录音、视频、眼动、压力传感器、复杂心理量表、大模型自动解读、多实验条件和大型模型训练不作为第一版依赖。

本地图片入口属于体验与材料准备功能：保留点击选择与拖拽，严格小于 20 MB，先明确支持 JPG/JPEG、PNG、WebP；格式、实际解码与尺寸共同校验。文案与字节阈值统一为 20 × 1024 × 1024 字节且不含边界。不能接受扩展名伪装，超大像素需要降采样或说明失败；临时对象 URL 及时释放。正式参与者不临时更换图片，研究者预先上传、审核并冻结实验材料。

# 2 产品入口、角色与页面清单

## 2.1 模式与角色

首页提供“自由体验”和“参与测试”。自由体验沿用选图、上传、简化预览、绘画与作品反馈；研究采集默认关闭。参与测试通过研究码进入，不能自行选择 A/B、修改笔触预算或跳过必需流程。

研究者入口与参与者入口分开。研究者负责配置、招募编号、异常管理和导出；评分者只访问被分配的匿名作品与评分表；参与者只访问自己的会话和结果。服务器校验角色与会话权限，不依赖隐藏按钮保护数据。

| 页面或模块 | 参与者看到什么 | 研究者/系统负责什么 |
| --- | --- | --- |
| 研究入口 | 研究说明、编号/研究码、设备检查 | 检查研究开放状态与重复进入 |
| 筛选与同意 | 零基础筛选、数据与作品用途、退出说明 | 保存同意版本与选择；不符合条件则退出研究入口 |
| 操作练习 | 不同练习图；相同长度的基础工具练习与指导操作演示 | 每人接受同样准备；练习不计入正式数据 |
| 任务前问卷 | 2 道单题，随后查看材料就绪页 | 保存题目版本、答案与时间 |
| 测试画布 | 固定参考图、统一工具、时间、完成/退出；B 另有阶段提示 | 限制功能、采集事件、控制截止时间 |
| 任务后问卷 | 4 道单题；待同步状态 | 冻结作品后采集，不延长绘画计时 |
| 轮间休息 | 2 分钟倒计时和下一轮说明 | 不展示上一轮成绩或两组优劣 |
| 结束访谈 | 3 个简短问题，可由测试者或研究者代录 | 保存文本、录入者角色与是否缺失，不默认录音 |
| 个人结果 | 两幅作品、实际时长、个人体验及评分状态 | 两轮任务与问卷完成后开放比较 |
| 研究工作台 | 不向普通参与者显示 | 配置、会话、待同步/异常、配对、评分、报告、导出 |
| 评分工作台 | 不向普通参与者显示 | 随机匿名作品、10 项独立评分、提交及修订记录 |

## 2.2 动效与反馈的执行规则

阶段切换、当前笔触方向和提交状态需要清楚；不增加强制观看动画。开始页确认后立即进入任务，结束确认应在首个完成点击时冻结画布，确认取消的规则需统一；建议正式测试使用明确的单次“完成并提交”按钮，避免弹窗期间继续作画。

测试画布采用中性语言，如“第 2 阶段 / 共 3 阶段”，不随机夸奖、不弹出庆祝、不提前公布得分。体验模式可保留更丰富的鼓励与完成反馈。两条件共享按钮反馈、计时与保存提示；B 的专有方向提示属于干预的一部分，需要版本固定。

支持减少动态效果设置；触控和平板优先测试，390 px 界面不得横向溢出，工具栏与安全区不能遮挡画布按钮。正式实验固定设备与输入方式，响应式适配不意味着可以混用设备而不记录。

# 3 实验全流程与控制变量

## 3.1 按程序执行的完整流程

流程：研究配置发布 → 编号登记/筛选/同意 → 服务端分配 AB 或 BA → 统一练习 → 第一轮前测 → 材料就绪 → 开始/绘画/结束 → 冻结作品和事件 → 后测/可靠保存 → 休息 → 第二轮相同流程 → 访谈 → 初步报告 → 两人评分 → 完整报告 → 数据集冻结/导出。

| 步骤 | 程序自动执行与保存 | 进入下一步的条件 |
| --- | --- | --- |
| 研究发布 | 冻结 protocol、材料、计划、问卷、评分、功能与分析版本 | 图像、计划、存储和评分清单验证通过 |
| 登记筛选 | 发放 P001 类匿名编号；记录是否满足预定零基础标准 | 筛选合格；不能把缺答当合格 |
| 知情同意 | 分别保存研究日志与研究作品评分许可，说明撤回途径 | 正式任务需要相应许可；不同意可转自由体验 |
| 条件分配 | 服务器按随机平衡区组分配，保存 order 与 pairId | 已分配者再次进入不重新抽签 |
| 练习 | 非正式材料、固定说明、统一时长与操作清单 | 研究者确认设备可用；不因某条件先做而多给练习 |
| 每轮前测 | 意愿与担忧各 1 题，1—7 分 | 提交或明确标为拒答，绝不填默认分 |
| 就绪 | 任务图与 B 计划预加载、校验哈希；空白作品层 | 图像与画布可用、前测已处理、无另一活动会话 |
| 开始任务 | 记录客户端起点、服务端时间和固定截止点 | 用户明确点击开始，加载耗时不计入绘画 |
| 绘画 | 两条件共同记录输入、工具、休息、切页与系统阻塞 | 完成提交、截止、撤回或故障触发终止 |
| 终止冻结 | 立即锁定输入、取消异步指导、固定事件末序号和作品快照 | 终止只能发生一次；之后上传与问卷独立进行 |
| 后测与同步 | 采集 4 题；保存事件、快照、问卷及服务端确认 | 上传失败可补传，不能假称后端保存成功 |
| 轮间休息 | 至少 2 分钟；可以延长但记录实际时长 | 首轮记录可靠保存，休息结束后开始第二轮 |
| 两轮结束 | 配对一致性检查，3 题访谈，结束说明 | 未完成两轮者也保留已采数据并标记不完整 |
| 评分与报告 | 两人独立评分、自动计算并更新报告版本 | 未评分显示待评分，不阻止已结束任务保存 |
| 冻结导出 | 导出一人一行分析数据、原始记录与清单 | 纳入规则、评分版本与文件校验可追溯 |

第一版面向成年人零基础使用者；筛选拟采用“未接受持续系统绘画训练、近期无规律绘画练习”的自报问题，具体时间阈值与题文在 P0 按导师意见冻结。程序能执行筛选规则，但不能验证参与者陈述真实性。

## 3.2 两条件能力表：在执行层限制

| 能力 | A 普通数字临摹 | B 阶段笔触指导 |
| --- | --- | --- |
| 参考图、任务目标、画布尺寸、背景 | 完全相同 | 完全相同 |
| 画笔、颜色选择、粗细范围、橡皮、撤销/重做 | 相同基础能力 | 相同基础能力 |
| 用户实际笔迹及失败/重试笔迹 | 全部保留，可自行修改 | 全部保留，可自行修改 |
| 轮廓/色块阶段、当前路径、起点/方向 | 无 | 有，固定指导配置 |
| 颜色/粗细提示 | 无额外推荐 | 显示推荐值，由用户选择或确认应用并记录 |
| 自动匹配、下一步、跳过、返回 | 不适用，统计值为 null | 可推进；区分匹配通过、手动下一步和跳过 |
| 描图底板、AI 补画、批量自动填充、笔迹替换、风格美化 | 禁用 | 禁用 |
| 图层和合成规则 | 同一组用户图层、同一操作能力 | 同一组用户图层；阶段可建议选择，但不替用户绘制 |
| 倒计时、完成/退出、休息、保存提示 | 相同 | 相同 |

B 的路径、顺序与参数提示作为完整辅助方案进行比较，研究结论不能单独归因于“笔触数量减少”或某个动画。颜色和粗细推荐属于干预，工具的可选范围保持一致。能力限制必须在命令入口和绘画内核执行，隐藏按钮但仍可调用自动补画是不合格实现。

## 3.3 同图重复与练习影响

AB/BA 随机平衡只能减轻顺序影响，不能消除同一图片画两次产生的学习迁移。报告必须显示顺序人数、按顺序的配对差值，以及第一轮两组的描述性结果。第一轮比较人数更少，不能替代主要配对结论。正式实验固定 1 张图便于控制变量，但论文结论只适用于该材料及相近简化画，不能推广到任意油画或照片。

建议用大小为 4 的平衡随机区组，每区组 2 个 AB、2 个 BA，服务端事务领取；研究者不能预览未来分配来挑选参与者。停止规则拟定为达到 24 个有效配对或最多 30 名正式入组者，以先到者为准，预试不计入；实际有效 AB/BA 数可能因缺失而不完全相等，应如实报告，不能为了凑平衡排除已有数据。

# 4 状态机、计时与异常处理

## 4.1 分离四种状态

任务状态：created → ready → running → submitted / timeout / withdrawn / technical_error。问卷、存储和评分另建状态，不把“画完了”“文件上传了”“报告完整了”合并为一个完成标志。

保存状态：local_pending → syncing → durable；失败转 retryable_error 或需要研究者处理。评分状态：unassigned → one_submitted → complete。报告状态：provisional → scored → frozen。一个任务可以已经 timeout，但仍在补传后测；这不应改变其绘画结束时间。

条件切换必须创建独立 sessionId、清空画布与工具状态、撤销栈和回调；复用同一个 pairId、participantId 与 taskImageHash。不能让首轮笔迹、指导位置或旧定时器泄漏到下一轮。

## 4.2 计时口径

任务内事件以 performance.now() 相对起点记录 offsetMs，避免系统时钟调整污染时长；另存带时区的 ISO 时间、服务器 receivedAt、设备与页面实例编号。墙上时钟用于命名和跨阶段顺序，单次任务时长以单调时钟为主。

taskElapsedMs 是从开始到结束的任务观察时长，包含看图、思考、换色与普通休息。固定 720000 ms 截止不因切页、主动休息或上传延长。系统延迟唤醒时，截止事件仍按预定截止点写入，并记录 observedAfterDeadlineMs；恢复后禁止继续落笔。检测睡眠或计时异常时标记质量问题，不能静默补出精确行为时间。

首个原始主指针事件与首个有效绘画动作分开计时。有效绘画拟定义为引擎真实提交的非橡皮笔迹且路径长度超过画布对角线 0.5%；点状标记是否计入须在预试结合画笔表现冻结。有效动作不是“与指导匹配成功”，两条件阈值相同。

## 4.3 常见异常的固定处理

| 场景 | 程序行为 | 数据与实验处理 |
| --- | --- | --- |
| 断网但页面继续运行 | 本地持久队列缓存；计时与截止照常；显示待同步 | 重连按序重放，同事件不重复计数 |
| 用户主动休息/页面隐藏 | 记录开始结束与区间；普通休息不停止总计时 | 重叠区间取并集；不能解释为紧张或不会画 |
| 刷新、浏览器崩溃、页面被回收 | 恢复已保存记录和待同步队列；不拼接新页面的单调时间 | 第一版将进行中任务标为 technical_error，研究者决定另开重测 |
| 刷新后发现旧任务已截止 | 保留故障发现时间、已确认事件和未知区间 | 不伪造丢失时段动作，按协议标记技术失败 |
| 重测 | 新 sessionId / attemptId，关联 supersedesSessionId | 原记录保留；不能重测到结果满意为止；按预设规则纳入 |
| 用户提前结束但作品未完成 | 保留 submitted 与实际结束时间 | 评分后判断是否达标，不能自动称“完成更快” |
| 主动撤回 | 停止任务；展示撤回范围与凭证 | 按同意约定处理日志、作品、评分和派生结果 |
| 重复点击完成/重复请求 | 终态幂等，返回同一确认 | 不产生第二条结束事件或重复文件 |
| 两个标签页同时进入 | 服务端活动会话锁和页面实例租约，后开页面只读提示 | 禁止两个输入源合并污染同一会话 |
| 不支持设备、作品导出失败、功能越权 | 停止继续任务并记录明确原因 | 不把技术失败混为退出或普通超时 |

# 5 数据埋点与指标字典

## 5.1 共同事件结构

每条事件至少包含 eventId、sessionId、pageInstanceId、seq、type、offsetMs、clientAt、payload、schemaVersion。服务端追加 receivedAt；participantId、condition、order、材料和协议版本以服务端会话关系为准，不信任客户端任意改写。

事件从底层绘画控制器统一发送，覆盖主指针、指针取消、最终落笔和工具命令。不能只在页面按钮或匹配成功回调里打点，也不能重复订阅 React 回调而重复计数。默认不记录完整逐点坐标、颜色轨迹、姓名、原图路径或访问令牌；路径长度、持续时间、输入类别等摘要足够支持本轮研究。用于评分的作品 PNG 单独私有保存。

| 事件组 | 必需事件 | 关键载荷/目的 |
| --- | --- | --- |
| 入组 | screening_completed、consent_recorded、assignment_created | 筛选结果、同意版本、条件顺序、pairId |
| 准备 | practice_started/ended、questionnaire_submitted、task_ready | 练习材料、问卷版本与阶段、资源校验 |
| 任务 | task_started、task_ended | 唯一开始/终止、截止点、终止原因 |
| 绘画输入 | stroke_started、stroke_ended、stroke_cancelled | strokeId、持续时间、归一化长度、是否实际渲染、取消/无效原因 |
| 指导反馈 | guide_evaluated、guide_advanced、guide_skipped、guide_revisited | planStrokeId、阶段、匹配结果、推进方式；A 不产生此组 |
| 工具修改 | tool_changed、parameter_changed、undo、redo、canvas_clear | 工具类别、用户选择/接受推荐、历史动作关联；避免无必要记录具体颜色 |
| 可见与休息 | visibility_changed、break_started/ended | 区间边界、主动休息与后台区分 |
| 系统状态 | system_block_started/ended、asset_error、capability_violation | 真正不可操作区间、故障代码、禁止命令触发 |

| 结束研究 | interview_submitted、pair_completed、withdrawal_requested | 问题版本、回答缺失状态、配对与撤回关系 |
| 评分分析 | rating_submitted/revised、inclusion_decided、dataset_frozen、export_created | 评分版本、排除原因、数据集清单和分析版本 |

服务端审计流与客户端行为流分开编号，避免服务端确认事件写回客户端队列造成递归。原始动作数、有效绘画数、橡皮动作数、取消数、匹配通过数分别统计。

## 5.2 论文核心指标的确定算法

| 指标 | 计算口径 | 缺失与解释 |
| --- | --- | --- |
| 作品完成度 | 每人评分总分 / 20 × 100，再取两位评分者均值 | 少一位评分者时最终分为 null，另显临时分 |
| 达标 | 平均完成度 ≥ 80，且预定主体结构项满足最低要求 | 80 为待预试冻结的项目标准；评分不足时为 null |
| 再次绘画意愿 | 两条件后测单题 B−A；另显示各自前后变化 | 1—7 单题，不拼成未经验证量表 |
| 满足感/信心/担忧 | 分项显示后测及适用的前后差 | 不用停顿次数推断心理状态 |
| 动笔延迟 | 首个有效绘画动作起点 − task_started | 全程无有效绘画为 null，另记 no_valid_stroke |
| 任务时长 | task_ended.offsetMs − task_started.offsetMs | 超时显示截止；技术失败另标可观察时长 |
| 达标完成时长 | submitted 且评分达标时取任务时长 | 超时、未达标、退出、故障均为 null |
| 实际绘画时长 | 非橡皮有效绘画区间的并集长度 | 不含匹配等待、换色、观察；不等于总用时 |
| 停留频次/时长 | 相邻有效绘画之间连续无绘画间隔 ≥ 5 秒 | 初始等待与末尾停留单列；不跨隐藏/休息/系统阻塞区间合并 |
| 停留速率 | 停留次数 / 可观察且可操作的任务分钟数 | 分母为总区间扣除隐藏、休息、系统阻塞的并集，零分母为 null |
| 明确休息/隐藏/阻塞 | 各类次数、各自时长、总不可操作区间并集 | 分类时长可能重叠，不能简单相加扣除 |
| 修订行为 | 橡皮、撤销/重做、清空次数及关联动作 | 解释为修改行为，不能直接称犯错 |
| 指导流程进度 | 已推进的计划笔触 / 计划总笔触 | 包括跳过须单列；仅 B 适用，A 为 null |
| 指导匹配数 | guide_evaluated 中通过的不同 planStrokeId 数 | 与重试动作数、作品完成度分开 |

停留不是自动测得的“犹豫”。5 秒是操作阈值，预试后冻结；可以附加 10 秒阈值的描述性敏感性结果，不临时挑选最显著阈值。处理事件时先建立有效观察区间，再在每段内计算相邻动作间隔，边界缺失标记 unknown，不将后台间隔算成前台停留。

任务内原始 summary 与报告派生 metrics 分开。派生指标带 metricsVersion、输入事件末序号、完整性状态和缺失原因。凡是 null 的字段必须原样保留，不使用 Number(null)、空字符串转数值或零值填充。

## 5.3 最小问卷与访谈

沿用上一份 Word 的题文。每轮前后均问：Q1“如果接下来有空闲时间，我愿意再画一张图”；Q2“想到再画一张图，我担心自己画不好”。每轮后额外问：Q3“我对刚才这次绘画体验感到满足”；Q4“我觉得自己能够完成类似的绘画任务”。统一 1＝非常不同意、4＝既不同意也不反对、7＝非常同意，显示完整刻度说明。前后共用题文，避免因措辞改变而误算变化。

这些是本项目的简短操作性题目，实施时以审核后的 questionnaire v1 文本为准，不声称已验证量表。可以拒答并记录 null 与 declined，不能强制选中间分；一项缺答不抹掉其余完整行为数据。报告按指标显示实际配对人数。

访谈沿用上一份 Word：①哪种方式更容易开始，为什么？②过程中最想停下来的时刻是什么？③哪一幅更让你有“这是我画的”的感觉，为什么？在两轮之后进行；可直接输入或由研究者代录并勾选确认，不在计时绘画中同步访谈。可另留非必填的改进建议框，不新增主要实验变量。

# 6 作品评分、对比分析与可视化

## 6.1 程序内的评分流程

研究者在材料发布前建立 10 项可观察清单，每项 0＝缺失、1＝部分呈现、2＝清楚呈现，并指定主体结构项。清单来自共同参考图和任务目标，不来自 B 的预览成品。两条件任务说明提供相同完成目标。

作品结束时导出统一尺寸、白色背景下的真实用户作品合成图，去掉参考图、引导线、光标、UI、计时器和自动生成笔触。用户自行画的轮廓与颜色层可以合成，不能把辅助提示层混入。

后台将作品随机编号与随机排序分给两位评分者。评分端不显示条件、任务顺序、用户编号、用时或指导进度，评分者提交前看不到另一人的分数。图像风格仍可能暴露条件，因此只称隐去条件标签，不承诺完全盲法。

每次评分保存 rubricVersion、raterId、逐项分数、理由（可选）、submittedAt 和 revision。自动显示两人差异与一致情况，较大分歧由预设规则标为复核；不能无记录地覆盖原评分。正式主结果使用事先规定的两人平均分；如修订，两位评分者各自保留修订记录与原因。

## 6.2 个人报告与研究报告

| 报告 | 具体图表/内容 | 开放与限制 |
| --- | --- | --- |
| 参与者初步报告 | 两幅作品、条件名称、观察时长、个人问卷、过程摘要 | 两轮及后测结束后；完成度显示待评分 |
| 参与者评分后报告 | 补齐完成度与任务达标情况 | 不评价个人绘画天赋，不把一次结果说成能力提升 |
| 研究者单人配对 | A/B 指标表、差值、双时间线、终止原因、事件质量与版本 | 只有对应研究权限可看；无第二轮时显示未配对 |
| 群体报告 | 样本流程、AB/BA 数量、完成度配对点线图、差值分布、意愿分布、达标四格表 | 每张图标有效配对数、缺失与排除 |
| 顺序检查 | AB 与 BA 分面差值、第一轮描述结果 | 提醒同图练习效应，不能自动据此宣称已完全控制 |
| 数据质量页 | 序号缺口、故障、异常时长、版本混用、未评分、未同步 | 与主结果分开呈现，导出时附纳入清单 |

双时间线用绘画、可观察间隔、主动休息、隐藏和系统阻塞表达过程；图例注明存在重叠与未知段。任务超时标记在统一 12 分钟位置。群体核心图用配对点线与差值，避免用单一柱状均值隐藏个体差异；不使用“能力雷达图”制造不受数据支持的能力评分。

## 6.3 分析规则与报告文本

分析单位是参与者配对，24 人两轮仍是 24 个独立参与者。先输出样本流程、有效配对、缺失原因与顺序，再输出 A/B 描述值、B−A 差值及不确定性。主要终点为共同完成度，关键次要指标为后测再次绘画意愿。

为减少小样本方法分支，建议默认：完成度报告配对平均差及 95% 区间；预设配对 t 推断，若预定诊断显示严重异常，则只保留描述性均值与预先声明的精确符号检验作为稳健结果，并明确二者检验对象不同。诊断规则、区间算法和启用条件必须在正式实验前写入 analysisPlanVersion，不由页面根据 p 值挑选。可在 P0 与导师直接改为全程精确符号检验，换取更简单的方向性结论。

意愿等有序单题以配对分布、中位数及精确符号检验呈现，平分单列并从符号检验有效样本中剔除。若完成度与意愿同时作为确认性推断，预先采用 Holm 校正这两项；其他指标标为探索性。达标四格表可附精确 McNemar 结果，但不扩展为新的主要结论。统计函数必须有已知答案用例，不能让大模型临场生成统计结论。

速度先结合完成度和达标比例解读。同为达标提交的配对可探索性比较用时，但需单列人数及选择偏差；不能删除未完成者后宣称系统提高速度，也不能把提前放弃当作快速完成。相同时间内完成更多是本轮更稳妥的效率证据。

程序采用固定文本模板，如“在 N 个有完整评分的配对中，B−A 的平均完成度差为 X 分”；同时显示区间与适用范围。不自动生成“已证明有效”“所有零基础者都会受益”等结论。若不足以估计区间或运行检验，显示不足原因，不产生假数字。

## 7.1 实体关系与版本

| 实体 | 关键字段/关系 | 保留原则 |
| --- | --- | --- |
| StudyProtocol | studyId、protocolVersion、问卷/评分/分析/功能版本、时限 | 发布后不可原地修改；改动形成新版本 |
| Material / Plan | originalSourceHash、taskImageHash、planHash、算法版本、阶段笔触、质量审核 | 原图、共同任务图与计划分清；正式会话绑定固定版本 |
| Participant / Consent | 匿名编号、筛选、同意版本、撤回凭证摘要 | 不混入真实联系方式；个人身份映射独立保管 |
| Pair / Assignment | pairId、participantId、order、随机区组、taskImageHash | 一次分配持久化，禁止重复抽签 |
| Session / Attempt | condition、period、attemptId、状态、起止、终止原因、替代关系 | 每条件一次有效尝试按协议确定，所有故障尝试仍可追溯 |
| EventBatch | sessionId、起止 seq、payloadHash、receivedAt | 顺序连续、幂等、不覆盖冲突事件 |

| Rating | artworkId、raterId、rubricVersion、逐项分、revision | 独立提交、可追溯修订 |
| Dataset / Report / Export | 纳入列表及原因、metricsVersion、analysisVersion、hash、生成时间 | 冻结版本可复算，最新报告不覆盖旧导出 |

## 7.2 第一版的持久化方案

建议研究现场使用单实例 Node 后端：SQLite 保存分配、状态、事件、评分与版本，私有文件目录保存作品和 JSON。该选择是单机研究版的部署假设；具体驱动在实施时按 Node/Next 构建兼容性核验后固定。数据库与文件位于持久磁盘，拟目录为 data/studies/，不进入 public/；实施时加入版本控制忽略规则。

通过 StudyRepository 和 StudyBlobStore 分离事务数据与大文件。沿用现有对象存储能力可以保存作品和导出，但不能仅用若干 JSON 覆写来实现多实例随机分配与事件事务。若需要公网多实例或临时容器部署，改用持久事务数据库及私有对象存储，并先通过部署重建恢复测试；不能把容器内 SQLite 或 /tmp 当作研究档案。普通体验的现有 OSS 统计通道保持独立。

后端生成文件路径和下载名称；客户端只能提交受验证的编号与会话凭证。研究者、评分者和参与者分权，正式数据与测试夹具隔离。作品不使用永久公开 URL；下载需要鉴权或短期授权。设置有期限的保留与备份策略并写入同意说明，具体期限随导师/研究要求在 P0 冻结。

## 7.3 可靠保存协议

1. 开始任务前，服务器创建并确认 session、条件、材料版本与活动页面。客户端建立本地持久事件队列，首个任务事件即时入队。
2. 绘画中每 5 秒或达到批量大小发送 checkpoint；每批携带连续 seq 范围、请求幂等键和内容哈希。客户端本地先落盘，再异步提交；使用 IndexedDB 等浏览器持久存储，遇到存储不可用应在开始前提示。
3. 服务端事务提交事件后才返回 ackedThroughSeq。完全重复批次返回同一确认；相同序号而内容不同返回冲突；有缺口返回 expectedSeq 要求从缺口重传，不假装完整。
4. 结束时先锁画布和计时，记录唯一 task_ended，固定最后序号；保存本地作品快照，然后上传私有作品。后测可独立提交，不让问卷拒答导致绘画数据丢失。
5. finish 校验事件末序号、唯一终态、权限、时长、禁用功能、图像/计划/协议哈希和作品存储状态。数据库与文件不假设跨介质事务：先写临时作品并校验，完成原子落位/对象确认后，再提交数据库引用和最终状态；中断可幂等重试，孤立临时文件后续清理。
6. 只有持久化完成才返回 stored:true 与 revision、rawSessionHash、artifactHash。未配置后端、写入失败或文件缺失必须返回失败/待同步，不能仅返回 HTTP 200 表示已保存。
7. 关闭页面通知只能补充普通同步；不能依赖 sendBeacon 完成最终保存。刷新后按故障政策保留已知数据和补传队列，不自动续算成连续实验。
8. 每日备份数据库、作品和导出清单；正式招募前执行一次恢复演练。修改评分生成新版本，原始终态事件与冻结会话不覆盖。

## 7.4 文件命名与导出内容

单条件文件名：P001-20260910T140000000+0800-control.json；另一条件使用 guided。以上仅为格式示例。测试时间采用该轮 taskStartedAt，带毫秒与时区；participantId 是匿名编号。后端按 studyId / pairId / sessionId / revision 组织目录，目录解决重测与修订碰撞，下载名保留“测试者—测试时间—测试模式”语义。

每条件 JSON 包含 schemaVersion、研究与参与者编号、pairId、sessionId、condition/order/period、版本与材料哈希、起止和终止原因、事件、分项问卷、作品私有引用/哈希、评分版本、派生指标、质量标记、纳入状态和原始记录哈希。评分尚未完成时字段为 null；后续导出形成新 revision，不改写原始事件。

同时支持：每人 pair.json（链接两条件和配对差值）；群体 participants.csv（一人一行，列出 A、B、差值和缺失原因）；manifest.json（所有文件哈希、数据集与版本）；图表 SVG/PNG 与可打印 HTML/PDF 报告。CSV 用于论文统计，JSON 是完整可审计记录。作品批量下载单独选择并校验权限。

上一份“测试记录结构示例.json”只作为需求示例保留，P0 会据最终字段建立正式 schema 与专用合成测试夹具；不得把示例记录导入正式参与者数据。

# 8 200 笔以内的阶段规划算法

## 8.1 范围、计数与共同参考图

优先针对主体清楚、背景简单、主色约 6—8 种的简化画。用户上传后先看到简化预览、预计笔数与适用提示；接受后才生成指导。复杂照片应降低纹理和细节复杂度，或明确建议换图，不保证任意油画 200 笔内保真。

硬上限约束最终可执行的独立笔触路径：一次从落笔到抬笔的连续动作算一笔。不能把一个按钮下的多条路径称为一笔，不能把极长蛇形覆盖线伪装成简单一笔，更不能先生成几千笔再截前 200 笔。用户重试、修改、橡皮和补画次数不受这个规划数量上限约束，实际动作另行记录。

正式材料采用同一份冻结的 taskImage；即使它由照片简化而来，A/B 都看这份简化图。originalSource 仅供材料溯源，不能给两条件不同目标。预算、评分清单和计划预览在招募前审核，参与者任务中不再选择简化强度。

## 8.2 输入、处理和输出

| 步骤 | 实施方法 | 必须得到的中间结果 |
| --- | --- | --- |
| 1 规范化 | 方向校正、透明底处理、等比缩放、降噪；保留原尺寸比例 | 统一坐标与颜色空间的 taskImage；预处理配置与哈希 |
| 2 简化色彩与区域 | 主色量化；SLIC 或连通区域候选；合并相邻近色小区块 | 有面积、邻接关系和主色的区域图 |
| 3 提取结构轮廓 | 连贯边缘/区域边界，抑制纹理碎线；路径简化 | 主体外轮廓和关键内部结构，不是全图所有边缘 |
| 4 标记重要内容 | 按主体、结构、区域面积和残差生成重要性；正式材料允许研究者校正 | 必须保留的主体/结构清单，与独立评分清单核对 |
| 5 生成可执行候选 | 轮廓线段；大区域宽笔覆盖；小区域短笔细节 | 每条候选具有 phase、regionId、路径、宽度、颜色与动作成本 |
| 6 分配预算 | 默认 180：轮廓 30 / 大色块 100 / 小色块 50；结构优先保底 | 允许阶段间重分配，整体始终不超过 200 |
| 7 逐笔选择并更新 | 在阶段约束内按重要区域误差改善/动作成本选择，立即更新虚拟画布 | 已选集合和剩余误差；删除重复、低收益笔触 |
| 8 动作约束与重排 | 检查长度、转折、可见起终点；过难路径拆分，再重新平衡预算 | 轮廓 → 大色块 → 小色块；阶段内邻近区域和近色优先 |
| 9 质量检验 | 用实际渲染器回放，检查关键主体、主色覆盖、数量和执行难度 | preview、qualityReport；不合格返回简化/改图原因 |
| 10 固定计划 | 固定随机种子和版本，序列化最终单笔列表并计算哈希 | plan、preview、budgetReport、可追溯 planHash |

这条路线借鉴上一份 Word 中 Hertzmann 的多尺度笔触、连贯线条和 SLIC 区域表示，有限预算、阶段配额与教学动作约束是本项目拟实现的组合，不是已有论文直接保证的“200 笔教学算法”。神经绘画方法留作后续比较或替代候选，不作为完成第一版的前置条件。

## 8.3 规划约束与拒绝条件

最终输出必须满足：1 ≤ strokes.length ≤ 200；phase 顺序单调为 outline、large_color、small_color；所有路径坐标有限且位于规范画布范围；关键结构有对应候选；连续动作难度满足预试冻结的路径长度、转折与宽度阈值。拆分超长路径、裁剪和最终重排之后重新计数，不只检查中间预算。

笔触收益评估与实际渲染保持一致；不能忽略遮挡关系而把画完后才暴露的残差留给截断列表。预算不足时优先合并近色小区域、减少背景纹理、降低非关键细节；仍不足就报告无法在当前目标下生成合格计划。不得用“全部拒绝复杂输入”代替交付：正式指定材料及预先选定的简单测试图必须生成经过审核的完整计划。

路径动作限制的数值需要通过真实设备预试确定，不从图像误差推断人类一定能画。默认 180 不是越接近越好；若平均每笔 5 秒，180 笔仅动作就需 15 分钟，必须减少预算和操作负担，不能随意延长正式条件的时限。

## 8.4 轮廓如何避免被后续颜色覆盖

采用共同的“轮廓用户层 + 颜色用户层”，轮廓用户层在颜色层上方合成，两条件都提供同样图层与切换能力。B 根据阶段提示该选哪层，默认由用户确认；A 可自由使用同一图层工具。导出时只合成用户绘制内容，不把计划轮廓自动烘焙进去。

若最终决定采用单层，必须改用不会吞掉关键轮廓的候选覆盖策略并重新验收；不能偷偷给 B 专用区域自动裁剪或自动补边。第一版优先采用共用双层方案，以便解释图层操作与公平性。

## 8.5 算法与体验的验收方式

建立至少 12 张内部材料：6 张主体明确简化画、3 张边界情况（细长结构、透明/横竖比例等）、3 张复杂输入用于验证简化或拒绝。它们是工程测试集，不等于 12 个实验条件。正式任务图必须包含在成功用例中，练习图必须不同。

每张图保存分阶段预览、笔数分布、主色、失败原因、生成耗时和质量检查。相同输入与配置产生相同计划哈希；所有成功计划都 ≤ 200，且不是截断旧序列。结构完整和实际可画性需人工看预览与预试确认，单一像素误差不能代替教学可用性。

体验模式用后台工作线程生成并显示可取消的进度，避免阻塞画布。正式实验只使用预生成并校验的计划，算法加载与计算不进入绘画计时。旧引擎可保留给体验功能，但正式测试禁止静默回退到未经审核的旧计划。

# 10 分阶段实施步骤与交付物

估时为一名开发者的净工作日粗估，假设已有项目可运行，不含招募、导师审核与评分等待；不是交付承诺。预计 20—33 个开发工作日，范围比上一份 Word 更细，新增了完整评分端、事务保存、故障恢复和数据集冻结。

| 阶段 | 顺序与工作 | 可审核交付物 / 完成条件 | 估时 |
| --- | --- | --- | --- |
| P0 协议与契约冻结 | 审核本计划；确认材料、工具对等、题文、评分、异常、分析和部署；建立正式 schema | protocol v1 草案、能力矩阵、事件/指标字典、页面流程、样例数据；关键定义不再含糊 | 2—3 天 |
| P1 共同画布与模式底座 | 抽取稳定内核；禁用测试自动绘制；分离作品/参考；加入共用双层与工具 | A 是干净普通临摹；B 保留真实笔迹；重置、冻结、快照和撤销正确 | 3—5 天 |
| P2 预算规划器与材料台 | 规范化、区域、轮廓、候选、预算、三阶段、预览与质量；完成正式材料 | 正式图生成 ≤ 200 笔完整计划；复杂图正确简化/拒绝；计划可冻结 | 4—7 天 |
| P3 研究后端与同步 | 持久仓储、分配、权限、事件队列、checkpoint、作品、finish、重试与备份 | 断网补传、重复请求、服务重启不丢已确认数据；后端可读取完整会话 | 3—5 天 |
| P4 全流程测试界面 | 入组、练习、前后测、两轮、休息、终止、访谈和实时状态；接入共同埋点 | 一人 AB 与一人 BA 都能全程在程序内走完，异常有明确分支 | 3—5 天 |
| P5 评分、报告与导出 | 匿名评分、配对指标、质量与顺序视图、统计、JSON/CSV/图表 | 原始记录 → 评分 → 报告 → 导出可核对；未评分不显示假完成度 | 3—5 天 |
| P6 联调与 6 人预试 | 自动回归、设备与存储演练、真实预试；调整材料/预算/文案 | 完整预试问题单和修复结果；正式材料能在时限内形成可区分结果 | 2—3 天开发，另加招募 |
| P7 正式版冻结与交接 | 锁协议和材料版本；备份恢复复核；导出研究执行卡 | 发布清单、版本哈希、研究者操作说明、正式数据空间 | 不另计，纳入 P6 收尾 |

依赖关系：P0 → P1 → P2；P3 在契约确定后推进；P4 依赖共同画布与可靠会话 API；P5 依赖已稳定事件和评分作品；P6 必须在完整闭环后执行；P7 只在预试修复与版本冻结后进行。阶段交付是进度检查和预览，不代表每个常规小修改都要重新询问许可；整体改造由本计划审核后的授权启动。

## 每阶段的具体执行次序

P0：先选定正式简化材料和共同完成标准，再固定 A/B 能力；随后冻结状态、事件、空值、重测和分析规则；最后把同意、问卷与评分文本做成版本配置。此阶段不招募正式样本。

P1：先给现有画布建立可控的用户作品导出与输入观察入口；再隔离参考与指导层；统一工具、图层、撤销与失败笔迹；最后接入体验与测试的能力配置，保留现有上传使用路径。

P2：先用正式目标实现可检查的区域/轮廓中间图，再加入预算选择和动作约束，最后调整顺序与阶段提示。每次优化同时看最终作品预览与逐笔可执行性，不只看总笔数。

P3：先做事务化分配与会话，再做持久事件和幂等，随后接入作品文件和 finish，最后验证断网、冲突、重启、备份与恢复。界面上的“已保存”只能使用这里的真实确认。

P4：按状态机逐屏接入，以合成夹具跑完整 AB/BA；统一计时、截止、休息和问卷；补齐故障与退出；最后调整文案和不阻塞输入的动效。

P5：先建立两评分者工作流，再从相同指标函数生成个人与群体报告；接着实现版本化数据集和文件导出；最后逐项核对图表、CSV 与 JSON 一致性。

P6—P7：先跑工程验证，再进行与正式数据隔离的 6 人预试。若简化画仍超过时间预算，优先降低笔数、减少切换与材料复杂度；更改后重新冻结，不能把修改前后版本混入一个正式实验。

# 11 验收用例与启动正式实验的门槛

## 11.1 工程验收清单

| 编号 | 验证场景 | 通过标准 |
| --- | --- | --- |
| A01 | 同一人分别跑 AB、BA 的合成完整流程 | 两轮条件、顺序、材料相同关系正确，无跨轮状态泄漏 |
| A02 | 普通临摹与指导的同一输入轨迹 | 共享工具与渲染一致；B 仅提示，未通过匹配也保留用户作品 |
| A03 | 尝试调用测试禁止命令 | 内核拒绝、记录异常，不能绕过隐藏按钮执行自动补画 |
| A04 | 导出空画布和已绘画作品 | 空作品纯白；作品无底图、星迹、光标或自动替换内容 |
| A05 | 原始触点、短轨迹、取消、重试与橡皮 | 各动作计数正确，不只统计成功匹配，无重复监听 |
| A06 | 预设事件时序含重叠休息、隐藏和阻塞 | 时长与手工答案一致；并集不重复扣除；未知段不计为停留 |
| A07 | 截止、后台恢复和结束连点 | 12 分钟截止后无新绘画；终止唯一；上传/问卷不增加绘画时长 |
| A08 | 断网、补传、批次重复/乱序/内容冲突 | 数据连续、幂等、冲突可见；未持久化不显示成功 |
| A09 | 页面刷新、崩溃与两个标签页 | 保留已知数据、技术失败分支正确、不伪造连续时间 |
| A10 | 后端重启及从备份恢复 | 已确认事件、作品、评分和导出可读取，哈希一致 |
| A11 | 规划器 12 张内部材料 | 每个成功计划 ≤ 200 且三阶段顺序正确；正式图完整通过人工审核 |
| A12 | 规划路径拆分与重新排序 | 最终笔数重算，不出现多路径伪装一笔或旧序列截前 200 |
| A13 | 两评分者独立提交与修订 | 彼此不可见未完成评分；平均分和版本正确；缺一份显示待评分 |
| A14 | null、0、拒答、缺轮、故障与未达标 | 不把缺失填零；每个指标分母可解释；超时不当达标完成时长 |
| A15 | 已知小样本统计夹具 | 配对差、区间/检验、平分处理和 Holm 计算与可信基准相符 |
| A16 | JSON/CSV/图表/报告互查 | 同一数据集与计算版本结果一致，一人一行，无重复尝试混入 |
| A17 | 角色越权与文件路径 | 参与者不能看他人；评分端不见条件；私有作品与原始事件不公开 |
| A18 | 本地上传和体验回归 | 点击/拖拽、格式与大小边界、横竖图、取消与重选正常 |
| A19 | 桌面/390 px/正式触控设备 | 无溢出与遮挡，起点方向清楚，操作不被动画锁住 |
| A20 | 版本冻结与退出撤回 | 正式材料不可原地替换；撤回影响相关数据及报告版本并留审计 |

测试采用领域单元用例验证计时、统计、状态和预算等高影响逻辑；端到端用例验证 AB/BA、持久化和导出。合成数据使用独立测试命名空间，不生成冒充真实受试者的记录。文案、颜色等低影响调整用页面预览验证，不为每个样式增加机械测试。

基础检查沿用项目要求：TypeScript → ESLint → 生产构建 → 桌面与 390 px 浏览器检查，再运行与本轮领域改造相关的测试。每阶段只对已变更范围补充必要检查；正式招募前执行完整闭环验收。

## 11.2 正式研究发布门槛

必须同时满足：固定协议与材料/计划/评分/问卷/分析版本；A/B 能力对等检查通过；正式材料规划 ≤ 200 且预试可执行；真实用户作品可评分；关键事件完整；已确认数据可在重启后恢复；报告与导出可复算；6 人预试问题已处理；研究者和评分者能按说明操作。

预试完成不等于研究假设得到证明。若 A 大量完全无法开始、B 所有人轻松满分或双方都做不完，应先调整共同材料/预算/时限方案并重新检查，再冻结正式版本。正式采集后不根据显著性调整排除、阈值或样本目标；必要版本变更独立标记并由研究方案决定如何分析。

# 12 主要风险、取舍与审核后的第一步

| 风险 | 本计划的取舍与处理 |
| --- | --- |
| 把过程进度误当作品效果 | 三套指标分开；完成度来自共同评分，程序提供评分工作台 |
| 200 笔但画不完整或难以执行 | 简化画优先；有限预算重新规划；关键主体和动作难度共同验收 |
| 指导自动美化导致不公平 | 测试禁用自动补画/替换，真实作品导出与能力执行层校验 |
| 同图重复产生学习迁移 | 随机 AB/BA、统一练习、顺序报告；论文明确残余局限 |
| 断网或容器重建导致数据丢失 | 本地持久队列 + 后端事务确认 + 持久目录/服务 + 恢复演练 |
| 页面刷新污染计时 | 第一版按技术失败保留记录并重新安排，避免复杂跨页面续时 |
| 多指标带来“总有一个显著” | 一个主要终点、一个关键次要指标；其他探索性，推断规则冻结 |
| 评分者推测出条件 | 隐去条件标签、随机编号、独立评分；不声称完全盲法 |
| 全流程太大拖延可用版本 | 先共同画布/规划/存储，再流程与报告；高级模型与额外传感器后置 |

用户审核后，建议先启动 P0，交付可直接用于开发的协议配置、正式数据 schema、材料候选与评分清单、关键页面流程。随后按 P1—P7 连续推进，提供每阶段可运行预览和验收证据。材料、题文与规则仍需用户/导师最终确认，但不应等到程序全部写完才讨论。

审核可以只回复“按建议默认方案执行”，或指出需要调整的阶段/默认值。对部署有公网、多设备同时测试等需求时，应在 P0 改定存储与权限方案；不能在正式数据已经采集后临时迁移未经验证的保存机制。
